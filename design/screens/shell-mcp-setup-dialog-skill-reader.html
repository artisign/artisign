Designing with artisign

artisign stores a design as files: tokens, components and patterns in the design system, screens as HTML that references them. Your job is to keep screens consistent and findable. These rules are not optional; the details behind them are in the full guide (get_guide).

1. Start every session the same way

  1. list_projects, then pass project to every call.
  2. Before you touch screens, read the project tree so you know the existing screens, their tags and their variants.
  3. Read every token, component and pattern. You cannot reuse what you have not read.
  4. Working on a ticket? Read its tag notes first: that is the feature spec.

2. Tag every screen and mockup you create or change

Tags are how humans and coding agents find your work. A screen without tags is lost work.

  • Ticket tag: the id of the ticket you work on, lowercase: chr-585.
  • Domain tag: the product area, kebab-case: checkout, settings.
  • Tags are cumulative. Read the current tags, append, then write.

3. Same page in another condition: a variant, not a new screen

variant_kindUse for
stateempty, loading, error, filled, dark theme
overlaysheet, modal, popover, menu, toast
stepwizard step, onboarding page

A different destination is a new main screen; the same page in another condition is a variant.
